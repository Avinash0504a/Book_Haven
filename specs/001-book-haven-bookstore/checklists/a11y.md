# Accessibility pass (T143, FR-077)

Method: `eslint-plugin-jsx-a11y` (recommended rules, no suppressions), code review of every
interactive control, and Testing Library queries by role and accessible name. A manual
keyboard-only walk in a real browser was NOT run in this session (no browser available to the
tooling); the rows marked "needs browser" must be walked by a person before release.

## Automated

- [x] `npm run lint` exits 0 with `jsx-a11y/recommended` enabled; no `eslint-disable` comments exist in `frontend/src`.
- [x] Every `<img>` in non-test components has an `alt` attribute (script scan, 0 missing).
- [x] Every icon-only `<button>` has an `aria-label` (script scan; 4 hits were false positives that render a label from `children`).
- [x] Tests locate controls by role and accessible name (reader font size, chapter select, wishlist toggle, star ratings, audio player).

## Findings fixed in this pass (not suppressed)

- [x] Star rating buttons in `ReviewForm.jsx` had `focus:outline-none` and no replacement: added `focus-visible` ring.
- [x] Help accordion header buttons in `HelpPage.jsx` had no visible focus: added `focus-visible` ring.
- [x] Text fields in `ReviewForm.jsx`, `ReaderPage.jsx` and `TopUpForm.jsx` showed focus by border colour only: added a 2px ring.
- [x] Fifteen Tier 2 files used class names absent from `theme.css` (`text-text-primary`, `bg-surface-elevated`, `border-border-default`, `text-brand-primary`, `bg-feedback-*`), so they rendered unstyled in both themes. All now use the theme tokens (`text-text`, `text-muted`, `bg-surface`, `bg-bg`, `border-border`, `text-primary`, `bg-danger/10`, `text-danger`, `bg-success/10`, `text-success`). `npm run check:tokens` passes.
- [x] Review form no longer pre-selects 5 stars, so a missing rating is possible and is blocked with "Rating is required" (US12-S4).
